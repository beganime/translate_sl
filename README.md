# TranslateSL

Локальная Django-студия для перевода PDF, DOCX, JPG и PNG по DOCX-шаблонам. Gemini читает документ, возвращает значения по заданным Jinja-переменным, переводит нужные поля на русский и собирает итоговый Word-документ.

## Возможности

- загрузка PDF, DOCX, JPG или PNG до 50 МБ;
- шаблоны DOCX и переменные вида `{{ full_name }}` в Django Admin;
- отдельная инструкция ИИ, обязательность и флаг перевода для каждого поля;
- Google Gemini Vision с JSON Schema — ответ всегда привязан к переменным шаблона;
- зашифрованное хранение API-ключа;
- двухпанельная проверка: PDF слева, редактируемые поля справа;
- повторный анализ, сохранение черновика, перегенерация и финализация;
- скачивание DOCX и, при наличии LibreOffice, PDF.

## Быстрый запуск (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py create_demo_template
python manage.py runserver
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). В `/admin/` откройте «Настройки ИИ», создайте активную конфигурацию и вставьте Gemini API key. Актуальная модель по умолчанию — `gemini-3.5-flash`.

## Как подготовить свой шаблон

1. Создайте обычный `.docx`, сохранив нужное оформление.
2. В местах подстановки добавьте простые переменные, например `{{ document_number }}` и `{{ full_name }}`. Не разбивайте одну переменную разным форматированием в Word.
3. Загрузите DOCX в «Шаблоны документов».
4. Добавьте переменные вручную во встроенной таблице или сохраните шаблон, выберите его в списке и запустите действие «Найти Jinja-переменные».
5. Для каждого поля опишите, что именно ИИ должен найти и нужно ли переводить значение.

## Настройки и безопасность

Переменные окружения можно задать по примеру `.env.example`. На постоянной установке обязательно задайте стабильный `DJANGO_SECRET_KEY`: от него зависит расшифровка сохранённого Gemini API key. Исходные и готовые файлы находятся в настроенном `MEDIA_ROOT`; в Google отправляется только выбранный документ. До появления общего диска production использует постоянный Docker volume `/data`.

Для PDF-предпросмотра приложение сначала использует LibreOffice (`soffice` в `PATH`), а на Windows — установленный Microsoft Word. Если оба варианта недоступны, приложение продолжит генерировать DOCX и покажет локальный HTML-предпросмотр. Word-конвертацию можно отключить переменной `WORD_PDF_CONVERSION=0`.
